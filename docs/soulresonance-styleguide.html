Principle

Four layers, one aesthetic.

Air

Warm paper light. The ground is never white; it carries the whole system and everything else is pressed out of it.

Trace

Precise programmable SVG geometry. Every brand mark is a path, a circle, a mask.

Paper

Deeper, warmer paper for what is personal, saved or felt. Because the ground is already paper, this one is darker and grainier so the difference is a material change, not a tint.

Spectrum

Digital colour, carrying every change, connection, activation and moment of meaning. Present, never decorative.

The aesthetic must feel

light, contemporary, human, precise, tactile, intelligent, alive

It must never read as

predominantly vintage, mystical, editorial or parchment-based

Radius scale

One scale, one role each, no exceptions: 8px for skeletons and inline chips, 14px for fields, metric tiles and status messages, 22px for cards and paper, 32px for demo stages and device frames, and a full pill for everything interactive: buttons, badges, eyebrows, the nav. The one deliberate break is the rounded corner at 52px, which marks a saved artefact.

Depth and relief

Surfaces are pressed out of the paper: a light edge on top, warm shade underneath, then a wide soft halo bleeding back into the ground. The halo is wider than the surface on purpose, so a raised element overlaps the paper instead of sitting inside a box.

Pressed

Light edge, warm inner shade, wide warm halo. The default for every surface.

Resonating

The same relief, lifted higher, with Violet and Rose light spilling into the halo.

+

Shadows and glows are never clipped. No overflow:hidden on a raised surface, on a section wrapper or on an SVG that carries a glowing path. Every SVG is set to overflow:visible and every grid keeps a gap wide enough for the halo. The single exception is a device frame, which has to clip its own chrome.

-

No hard drop shadow, no glass, no cold grey shadow. The shade is always the warm one, rgba(138,107,69, …).

Core visual grammar

Everything below is SVG paths, circles, masks, gradients, clipping and opacity, animated with CSS or JavaScript.

Trace

A trace represents a person, state, process or direction. Cubic Bézier, 1.25 to 2px stroke, round caps, no fill, limited directional changes, controlled asymmetry. Never an arbitrary sine wave.

Echo

A second trace following the primary at 2 to 4px offset, 30 to 55% opacity: resonance, memory, influence. Violet, Blue, Rose or Pink, each carrying a soft glow so colour reads as light on the warm ground.

Gap

Important shapes stay deliberately incomplete: autonomy, potential, breathing room, unresolved possibility. Gaps live in circular graphics, dividers, component edges, timelines, navigation and animation.

Bridge

A short cubic Bézier connecting two otherwise independent traces: relationship. Optional spectral stroke. No arrows, no technical connector style.

Spectrum

Violet → Blue → Orchid → Rose → Pink. It marks everything that changes, connects, activates or becomes meaningful, roughly 40% of what you see.

How an edge is drawn

+

The edge is a 2px ring on the surface outline, so it follows the corner radius into the curve instead of stopping at the straight part.

+

It always fades out, and the fade is measured in pixels, not percent: solid for the first 9px, gone by 44 to 46px. A small metric tile and a large card therefore show an edge of the same visible length. An edge never ends on a hard cut.

+

The rounded corner is a real radius change, 52px on that one corner, with the edge tracing the arc and fading out on both sides of it. The corner is rounded away, never cut off.

+

The partial edge is the bottom edge with a second, horizontal fade at 42 to 74%. That one stays in percent because its length is the message: how far the work got.

+

The edge carries the spectrum glow, so it lights the paper immediately around it.

-

One edge per surface. Never two, never a full ring.

Markup: <span class="sr-edge e-bottom"><i></i></span> inside the surface. The span carries the fade mask, the inner element carries the ring.

Responsive

Mobile first, in the CSS as well as in the thinking.

Breakpoints

FromWhat arrives
baseThe phone layout. One column, stacked metrics, bottom navigation, tables scroll inside their own container, side rail hidden.
640pxThe second column: two-up grids, swatch pairs, three metrics in a row, tables become real tables, section padding grows.
768pxThe split hero, the twelve-column grids with their 5 and 7 spans, and the side rail in the application.
1024pxFour-up grids, the five colour swatches in one row, the floating nav pill at full width.
1180pxThe scroll trace appears in the left margin, where there is finally room for it.

Every query is min-width. The base rules are the small screen, and each breakpoint only adds capacity. There is not a single max-width query in the stylesheet, so nothing has to be undone for phones.

Rules

+

Tap targets stay at 44px minimum, on every viewport, including the bottom bar.

+

Grid children carry min-width:0, otherwise a wide table or a long token stretches the page.

+

Edge fades are in pixels, so an edge looks the same on a phone tile and a desktop card.

+

Wide content scrolls inside its own container. The page body never scrolls sideways.

-

Never 100vh for a full-height screen. Use 100dvh, or the mobile browser bar cuts the layout.

-

The side rail is not shrunk into a phone. It becomes a bottom bar, and the active item carries the spectral edge.

Which patterns this system uses

A documentation and system surface takes the quiet end of the catalogue: basic reveal, staggered group, line draw and hover micro-interactions. Nothing else.

+

Traces draw themselves once when they enter the viewport. Drawing is the brand, so it is the one thing that animates.

+

One perpetual signal only: the bridge endpoint breathes while a connection is open.

-

No smooth-scroll layer, no pinned chapter, no parallax, no ambient effect on a system surface.

-

No scroll listener. IntersectionObserver or a CSS scroll timeline, nothing else.

Guards, all mandatory

+

prefers-reduced-motion: everything visible, movement removed, opacity kept, loops stopped.

+

Reveals run once. Scrolling back up never replays them.

+

Text splits wait for document.fonts.ready.

+

transform and opacity only. Never width, height, top or left.

+

will-change during the sequence only, then back to auto.

+

Hover states only behind (hover:hover) and (pointer:fine), each with a focus-visible equivalent.

Implementation test

Every core visual must answer yes to all six.

  • Can this be recreated as SVG?
  • Can its geometry be parametrised?
  • Can it be animated with CSS or JavaScript?
  • Does it remain recognisable without texture?
  • Does it work in monochrome?
  • Does it stay understandable at 320px width?

If not, it is not a core SoulResonance brand element.

Monochrome proof, same mark without colour

Recognition rule: a major visual normally combines at least three behaviours. Here Trace, Echo and Gap.
